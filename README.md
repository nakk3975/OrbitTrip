# OrbitTrip 0.2 — fixed-moment travel planner

외부 여행 API 없이 동작하는 비공개 인터랙티브 프로토타입. Node 22+ / HTML / CSS / JavaScript ES modules.

## 실행

```sh
npm ci
npm start
# http://localhost:3000
npm test
npm run build
```

## 사용자 흐름

1. 다크모드의 큰 지구로 시작합니다. 드래그·방향키로 회전하고, 세계지도 버튼으로 넓은 지도/국가 카드 탐색으로 전환합니다. 확대·축소·초기화·국가 검색도 지원합니다.
2. 국가 선택 후 상세 계획 화면으로 이동합니다. 날짜별 도시, 활동 시작·종료 시각, 여행 속도를 정합니다.
3. 고정 방문/예약과 기차 이동을 추가합니다. 하루 전체, 오전/오후 시간 예시 또는 직접 입력을 지원합니다.
4. 예약 시간을 그대로 유지하며 이동과 대기 시간을 고려해 남는 시간을 채웁니다. 빈 시간이 남으면 휴식 또는 수동 추가에 사용할 수 있습니다.
5. 결과를 직접 수정·삭제·추가하고 JSON으로 내보낼 수 있습니다. 설정 변경 때 기존 결과를 즉시 지우지 않고 재추천 필요 상태를 표시합니다. 재추천은 고정 일정을 유지하며 자유 일정 편집은 대체합니다.

### 도쿄 예시

고정 일정이 없는 4일 이상 도쿄 여행에서 `도쿄 4가지 방문 예시 추가` 버튼:
- 1일차 디즈니랜드: 하루 전체, 이동 포함, 다른 추천 없음.
- 2일차 가스카베: 10:00–12:00 고정. 이동 여유를 반영한 활동 시작 추천.
- 4일차 오다이바: 13:00–15:00 고정.
- 4일차 팀랩 플래닛: 16:00–18:00 고정.

예약 전 15분, 기차 출발 전 30분, 도착 후 20분 여유. 중심역을 첫 출발점으로 가정합니다. 활동시간 추천은 고정 일정과 이동 추정치를 사용하며 실제 개장 시간을 뜻하지 않습니다. 야간을 넘기는 일정은 미지원. 겹치는 예약·부족한 이동·활동시간 이탈은 생성 전에 알려줍니다. 수동 편집 후 충돌은 결과에 경고합니다.

## 지도

Natural Earth 공용 지형 데이터를 빌드 결과에 포함했습니다. 출처는 `public/MAP-LICENSE.txt`.
- 세계지도: 날짜변경선에서 분할한 폴리곤.
- 지구: 평면 해안선 마스크를 가시 반구의 각 픽셀에 역투영. 숨은 꼭짓점을 직선으로 연결하지 않아 회전 시 찢어진 삼각형이 생기지 않습니다.
- 360° 회전 수학 테스트와 6개 방향의 실제 브라우저 캡처 검증.
- 첨부 참고 영상의 넓은 지도 중심 탐색 방식을 참고했으며 영상 화면·에셋·브랜드를 복사하지 않았습니다.

## 데이터 및 저장 범위

일본(도쿄·교토·오사카), 한국(서울·부산), 프랑스(파리), 이탈리아(로마). 장소 좌표·소요시간은 계획용 근삿값입니다. 식사는 식당가 추천이며 실시간 평점·영업시간·예약·교통편·요금은 조회하지 않습니다. 경로도는 직선 연결도입니다. 내장 추천 장소가 소진되면 직접 장소와 좌표를 추가할 수 있습니다.

localStorage에 국가별 초안을 보관합니다. 기존 v1 저장을 읽고 v2로 옮기되 v1 원본 키를 삭제하지 않습니다. 같은 브라우저/사이트에서만 복원됩니다. Render 서버에 DATABASE_URL을 설정하면 Neon에 국가별 일정을 저장·불러올 수 있습니다. 브라우저 자동 저장과 서버 수동 저장은 별개입니다. 서버 불러오기는 현재 브라우저 일정을 대체하기 전 확인을 받습니다.

## 배포

`npm run build`로 정적 배포용 dist를 만듭니다. 기존 비공개 호스팅의 전용 설정은 이 저장소에 포함하지 않습니다.

`render.yaml` 및 `deploy/render.yaml`: Render 배포 설정. 프로덕션은 APP_USER/APP_PASSWORD가 없으면 시작하지 않습니다. HTTPS 환경에서 HTTP Basic 인증으로 보호하며 `/health`만 비인증 응답합니다.

`deploy/neon-schema.sql`: Neon 일정 저장 스키마. 런타임은 SELECT/INSERT/UPDATE만 가진 별도 역할을 사용하며 RLS로 소유자를 구분합니다. DATABASE_URL은 Render 비밀 환경변수에만 넣습니다. 서버 저장은 revision 조건으로 다른 탭의 변경을 보호합니다.

### 이동수단 비교
자동차·대중교통·도보 선택을 추천, 활동시간 제안, 빈 시간, 도착 가능 여부에 반영합니다. 결과에서 변경하면 예약과 편집한 방문 시각을 유지하며 충돌을 다시 계산합니다. 추천 재생성은 명시적으로 실행합니다. `routeEstimate`가 오프라인 교통 추정의 경계이며 향후 지도/교통 제공자로 교체할 수 있습니다. 현재 구간 표시는 이동 흐름이며 실제 도로, 노선, 환승 또는 통행 가능 여부를 계산하지 않습니다. 외부 API 및 인증키를 사용하지 않습니다.

## Render · Neon 연결

Node 22 이상. Render 환경변수: `NODE_ENV=production`, `APP_USER`, `APP_PASSWORD`, `DATABASE_URL`(Neon pooled URL, TLS 인증서 검증). `/health`를 제외한 화면·파일·저장 API는 HTTP Basic 인증으로 보호됩니다. 공유 계정 1개를 사용하는 개인 프로토타입이며 회원가입 서비스는 아닙니다.

Neon 프로젝트: `OrbitTrip` (`late-mud-28122960`), Singapore. 런타임 역할은 `orbittrip_app`. `/api/storage`는 연결 설정 유무, `/api/drafts/:country` GET/PUT는 국가별 저장/조회를 제공합니다. DB 비밀번호는 Git에 포함하지 않습니다. 실제 Render 배포는 작업 공간 확인 후 진행합니다.

DB 통합 검증: `node --env-file=.env.local tests/storage.integration.mjs`. 실행 환경에서 DB 호스트로 네트워크 접근이 가능해야 합니다.

## 공개 탐색 및 DB 카탈로그 (2026-09-21)

Render에서 `PUBLIC_ACCESS=true`이면 로그인 없이 국가 검색·지도·추천·브라우저 저장을 이용할 수 있습니다. 기존 서버 일정 API는 계속 인증이 필요하고 비로그인 화면에는 서버 저장 버튼을 표시하지 않습니다. `APP_USER/APP_PASSWORD`는 기존 개인 일정을 보호하기 위해 유지합니다.

Neon `orbittrip.catalog_country`에 16개국·19개 도시·102개 추천 장소를 저장했습니다. `/api/catalog`를 통해 읽으며 서버 캐시 5분을 사용합니다. DB 장애 시 번들 목록으로 대체합니다. 추가 국가: 영국·스페인·독일·스위스·미국·캐나다·호주·뉴질랜드·태국·베트남·싱가포르·대만. 각 추가 국가는 대표 도시 1곳부터 제공합니다. 기준 지점은 도시 좌표이며 실제 역을 의미하지 않습니다. 여행 장소와 시간은 계획용 근삿값입니다. 카탈로그 원본: `data/catalog.json`.

## 세계 도시 탐색 확장

- 250개 국가·지역, 5,683개 도시. GeoNames 인구순 최대 50개 도시/국가와 별도 관광 도시를 합쳤습니다. 전체 행정구역을 빠짐없이 수록한 것은 아닙니다. 6개 무인·특수 지역은 도시가 없어 선택이 비활성화됩니다.
- 추천 장소 482개, 134개 도시 수록. 나머지 도시는 추천 준비 상태를 표시하며 직접 방문 입력을 지원합니다. 운영·예약·이동은 실시간 검증 데이터가 아닙니다.
- 한국 17개 시·도 필터, 도시 검색, 도시별 장소 미리보기와 전체/특정 날짜 적용. 해외 지역명은 일부 원문을 유지합니다.
- 메인 목록은 검색할 때만 열리고 접두어 일치 국가를 우선합니다. 전체 목록은 별도 대화상자와 대륙 필터로 제공합니다.
- 지도는 보이는 국가를 이름표로 표시하고 겹침을 최소화하여 배치합니다. 확대/이동 및 검색으로 밀집 지역을 탐색합니다.
- 로그인/서버 저장 UI는 제거했습니다. 공개 이용은 브라우저 저장이며 기존 개인 서버 기록은 보호됩니다.
- 데이터 출처/라이선스: public/CATALOG-LICENSE.txt. DB 시드: scripts/seed-catalog.py (관리용 URL은 환경변수로만 전달).
- 브라우저 탐색 검증: tests/catalog.browser.cjs.

## Geoapify 연결 (2026-09-22)

Render의 `GEOAPIFY_API_KEY`를 사용합니다. 키는 서버 전용이며 응답·프런트엔드·Git에 포함하지 않습니다. 이 절이 위 오프라인 지도/교통 설명을 대체합니다.

- 도시 둘러보기 또는 방문/장소 추가에서 관광지·음식점·카페를 검색합니다. 도시 기준점 반경 5/15/30km, 이름 필터, 최대 20곳입니다. 지역과 등록 언어에 따라 누락될 수 있으며 평점순 맛집 추천은 아닙니다.
- 검색 결과를 추천 후보 또는 고정 방문/직접 일정에 추가합니다. 후보는 해당 브라우저의 국가별 일정과 함께 저장됩니다. Neon 카탈로그를 일괄 덮어쓰지 않습니다.
- 일정 결과의 '상세 지도 열기'는 Geoapify raster tiles + Leaflet 1.9.4를 사용합니다. 지도와 장소 출처를 표시합니다.
- '오늘의 실제 경로 조회'는 자동차/도보의 현재 날짜 구간만 조회합니다. 조회 성공 구간은 실선, 나머지와 예약한 철도 이동은 직선 점선입니다. 도로·보행망 기반 예상 시간이며 실시간 교통이나 운행 여부는 보장하지 않습니다. 자동차에는 주차 여유 8분을 추가합니다.
- 조회 결과는 이동시간·여유시간·충돌 경고에 반영됩니다. 예약 및 방문 시각은 자동 이동하지 않습니다. 다시 추천 시 조회한 구간은 활용하고 미조회 후보 구간은 기존 추정치를 사용합니다.
- 대중교통은 추정치를 유지하고 API를 호출하지 않습니다. 구간별 Google Maps URL을 통해 실제 노선·환승을 별도로 확인합니다. Google API 키나 과금 연동은 없습니다.
- Places/route 캐시 1시간, 타일 서버 캐시/브라우저 캐시 24시간. 서버 캐시는 최대 32MiB/1,000개입니다. 동일 요청을 합치고 업스트림 간격을 최소 300ms로 제한합니다.
- 자체 보수적 조회 예산: 단일 서버 프로세스의 UTC 일자당 2,000 단위(검색 2, 경로 4, 타일 1). 실제 Geoapify 크레딧과 동일한 계수가 아니며 재시작 시 초기화됩니다. 서비스 전체 과금 상한을 보장하는 장치는 아닙니다. 무료 플랜을 유지하고 제공자 사용량도 확인하세요. 자동 업그레이드는 구현하지 않습니다.
- 없는 키/실패/한도 초과/미지원 모드는 명시적으로 표시하고 기존 수동 입력·추정 동선을 유지합니다. 공개 API는 고정된 업스트림·입력 검증·호출 제한만 허용합니다.

검증: `npm test`, `node tests/geo.browser.cjs` (Playwright/Chromium 필요). 테스트는 가짜 제공자 응답으로 검색→예약 추가→경로 반영→지도 표시, 예약 보존 및 대중교통 미호출을 검증합니다. 실제 제공자 확인은 배포 후 별도로 수행합니다.

## 지역별 추천 개선 (2026-09-22)

- 도쿄 기본 후보 15곳을 30곳으로 보강하고 6개 지역으로 묶었습니다. DB 카탈로그를 읽은 뒤에도 동일한 버전 관리 보강 데이터를 합칩니다. 체류시간·좌표는 계획용이며 운영시간이나 예약 가능 여부를 검증한 자료가 아닙니다.
- 전체 여행 기간에 지역을 먼저 배분한 후 날짜 안에서 순서를 정합니다. 미래 고정 예약과 가장 가까운 지역을 해당 날짜에 우선 배정하고, 예약 사이의 자유 일정은 최대 5곳의 순열을 비교해 이동·대기를 줄입니다. 글로벌 최적 경로를 보장하지 않습니다.
- 음식점 때문에 먼 지역으로 이동하던 과도한 점수 가중치를 제거했습니다. 자동 식사 추천은 하루 최대 1곳이며, 인접한 관광지와 같은 지역에 배분합니다.
- 후보가 부족한 도시는 추천 버튼을 누를 때 Geoapify 관광지·음식점 조회로 보충합니다. 생성 1회 최대 8개 조회, 기존 서버 캐시·예산 제한을 따릅니다. 실패·후보 부족 시 이유를 표시하고 장소를 만들어내지 않습니다.
- 기존 브라우저 일정은 유지하며 '다시 추천'으로 새 방식을 적용합니다. 외부 조회 중 조건이 바뀌면 이전 요청을 현재 일정에 덮어쓰지 않습니다.
- 회귀 검증: 기본 도쿄 5일이 각 5곳으로 채워짐, 우에노·아메요코 같은 날 연속 방문, 도쿄타워·조조지 인접 방문, 미래 예약 지역 보존, 후보 자동 보충/실패, 기존 고정 이동·하루 일정 보존.

## 공항·숙소 중심 계획 (2026-09-22)

- 숙소 이름/주소 검색 또는 좌표 직접 입력, 숙박 기간별 여러 숙소, 체크인 가능 시각·체크아웃 마감 및 수속시간을 지원합니다. 체크아웃 날짜는 숙박 범위에서 제외합니다. 기간 겹침과 여행 밖 숙소는 차단합니다.
- 날짜별 출발은 전날 숙소, 귀환은 그날 숙소입니다. 첫 숙소 체크인 전에는 도시 기준점에서 시작하며, 도착편이 있으면 공항이 출발점입니다. 숙소 미등록 날짜는 도시 기준점을 사용합니다.
- 도착편은 여행 시작일 현지 도착시각 + 입국/수하물 여유로 계산하고 공항→숙소 이동과 체크인을 먼저 넣습니다. 늦은 도착은 수속을 마칠 수 있도록 종료시간을 늘리며 관광을 억지로 채우지 않습니다. 출발지 날짜·시각은 기록용으로만 저장해 시차를 잘못 계산하지 않습니다.
- 출국편은 여행 마지막 날의 현지 출발시각에서 공항 수속 여유를 뺀 시각까지 도착하도록 역산합니다. 이른 출국은 출발·체크아웃 시작을 자동으로 앞당깁니다. 기본 여유 60분/180분은 사용자가 수정하는 계획값이며 공항·항공사 보장값이 아닙니다.
- 공항 수속·체크인이 자정을 넘기는 경우 현재 지원하지 않습니다. 항공편 날짜는 여행 시작/마지막 날짜에 연동합니다. 숙소 체크인 가능 시각 이후 계산한 수속과 기존 예약이 충돌하면 자동으로 예약을 옮기지 않고 오류를 표시합니다. 체크아웃 후 짐 보관이나 숙소 영업 여부는 별도 확인이 필요합니다.
- 귀환 이동을 추천 종료·빈 시간·충돌 검사·지도·실제 자동차/도보 경로 조회에 반영합니다. 숙소가 다른 도시라면 기존 도시 간 고정 이동을 등록해야 합니다.
- 나라/도시를 선택해 추천하면 부족한 후보를 최소 24곳 목표로 보충합니다. 도시의 '추천 장소 더 확보하기'로 관광·음식점·카페를 더 조회할 수 있습니다(목표 최대 120곳, 요청당 8회 제한, 실제 확보 수는 지역에 따라 다름). 숙소 주변을 우선 조회하고 저장된 후보를 재사용합니다. 전 세계 DB를 미리 모두 수집하는 방식은 아닙니다.
- 숙소·항공편·추가 장소는 기존 국가별 브라우저 초안에 저장합니다. 주소 검색어는 Geoapify로 전달되며 키는 서버에만 유지합니다. `/api/geo/location`은 국가 필터를 적용한 주소 검색입니다.
- 검증: `npm test`, `tests/logistics.browser.cjs`. 공항 도착/출국, 숙소 변경/귀환, 도시 간 이동, 불가능한 연결 차단, 모바일 및 새로고침 복원을 포함합니다.

### 주소로 숙소 위치 선택
숙소 입력은 주소 검색을 기본으로 사용합니다. 사용자가 도로명·번지 주소를 입력하고 결과를 선택하면 좌표를 내부에 저장하며 위도·경도 입력칸은 표시하지 않습니다. 숙소명 검색은 별도로 선택할 수 있으며 선택 도시 반경 30km의 Geoapify accommodation 데이터를 사용합니다. 검색 결과가 없다고 실제 숙소가 없는 것은 아니며 등록 언어·데이터 누락으로 일부 호텔·지점이 검색되지 않을 수 있습니다. 주소 검색은 선택 국가 안에서 도시 인접 결과를 우선합니다. 편집 시 기존 주소·위치를 보존하며 기준 도시 변경 시 위치를 다시 선택해야 합니다.
